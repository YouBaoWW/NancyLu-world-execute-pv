# 02 · 客户端与逐字歌词

**性质：根据最终 v3 代码与审核要求重建的可复制模板。** 具体实现对应 `src/nancy/client.js`、`dialogue.js`、`lyrics.js` 和 `avatar-data.js`。不是 Codex 产品功能文档。

## 完整桌面

```text
为 NancyLu PV 用 Canvas 2D 绘制可复现的 Codex 风格完整桌面。设计坐标1920×1080：主窗口约(72,62,1776,956)，左侧任务列表，中间对话，右侧代码与终端，底部输入框约(340,798,1024,167)。这些是当前工程的布局基准，修改尺寸时整体重新计算，不保留失效硬编码。

用近黑背景、冰白文字、电蓝线条、冷灰分隔。模型名精确为 NancyLu，使用用户指定的像素头像；头像像素原色与形状不变，按颜色行程或矩形逐格绘制，透明区域不刷成方形黑底。

模型工具栏必须有闪电形 Speed、思考强度图标、低/中/高/极高四档。水平滑杆为蓝到紫的渐变圆角胶囊、白色圆形旋钮；旋钮和填充长度共用同一进度，不能一边滑动一边脱离轨道。前段由光标调节，断连后自行提高，高潮突破轨道转化为权限与数据通道。

所有状态由绝对歌曲时间t和明确phase决定，禁止Date.now、无种子随机或依赖上一帧。先画一次完整客户端；组装时以六块不重叠的区域显示同一布局，裁切发生在区域偏移之前。组装后只渲染一套窗口、输入框与工具栏。
```

## 完整 LRC 进入问答

```text
把用户提供的完整LRC解析为行级数据，至少含start、end、text、role、effect、keyword。使用完整句子组织USER与NancyLu的问答，保留最近历史与当前句；不要用孤立几个剧情字替代整句歌词。

USER的当前句在真实输入框的文本带内逐字输入，随后进入消息历史；NancyLu回复在会话正文出现。普通界面阶段不得再画一个悬浮字幕覆盖真实输入框。输入文字区域与模型/Speed/强度栏分离：当前工程文本带约811–853高程，控制栏约855以下。超长句测量换行或滚动，不遮挡旋钮和按钮。

非完整客户端场景，将左侧函数描述、人物旁长句做成蓝白浮动终端/对话窗：标题栏、NancyLu头像/名称、角色标签、当前歌词、简短函数响应。空间不够时优先保留当前歌词，再保留最近历史，最后减代码行；小窗口只留当前句也不能截断。

保持lyricTime是实际歌曲时间。客户端组装可以冻结UI布局时钟，但不能把用于静态布局的t=8误当成歌词时间。
```

## 六类字母效果

```text
用Array.from处理字符，测量字宽与实际换行。先求每行已经揭示的精确字符数，再应用表现效果，最终文字必须回到固定基线与完整拼写。

type：逐字打入，带短暂插入光标；
decode：字母在自己位置经历短暂代码符号解码后锁定；
scan：狭窄扫描带揭示字符，不能成为遮挡整句的宽黑条；
rise：字符轻微上升到基线并淡入；
packet：字母按小数据包依次到位，包之间有节奏间隔；
glitch：短时局部横移/切片后稳定，不在歌词持续期反复抖动。

同一段通过语义与角色分配效果，不给每句话完全相同的打字速度和动作。历史消息固定为完整文本且适度降亮；当前消息最清晰。

现有LRC只有行级锚点，句内字母可用元音1.22、普通辅音0.76、空格0.22、标点0.4的权重分配时间。这是估计，不是实测逐音素同步。长乐间不要让一句歌词慢打十几秒；为间隔与关键词分别设置合理保留时长。
```

## 两分钟附近的会话戏剧

```text
将约115–125秒的离线/孤独段做成可读的大对话历史，保留完整歌词的重复、等待、撤回与未发送状态，右边放蓝白字符NancyLu。客户端与人物不能缩成画面中心的两个小点。

撤回过程分层进行：历史行先降亮，少量字符离开原位置，在侧边空白带收束成旋涡，再被抹除；当前歌词阅读区保持清晰。用消息被删除造成的空洞表达上下文流失，不能仅靠全屏噪声。动作由绝对时间与固定索引计算，任意跳转得到相同状态。
```
