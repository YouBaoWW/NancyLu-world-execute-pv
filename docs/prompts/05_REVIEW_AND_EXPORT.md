# 05 · 审核、导出与复现

**性质：根据制作流程和最终导出工具重建的模板。** 验证结论必须来自本次实际运行；重新导出后不能直接沿用历史 v3 的通过记录。

## 关键帧与短片

```text
先从最终renderFrame(t)输出六张1920×1080关键帧及总览图，交给用户审核后再推进全片动画导出。不要用独立手工海报伪装成最终渲染关键帧。

六张标准时间为：23.2秒完整客户端、57.5秒Speed/思考强度、67.8秒契约人物、84.32秒猫爪ENJOYMENT、146.1秒系统崩坏、169.4秒执行权高潮。时间均是歌曲时间。修改过的镜头再补切入后、主事件、结束前的帧，检查半身遮挡、面部残白、白肤紫瞳、手指、完整歌词与UI不重复。

关键帧通过后先做猫爪、高潮、太阳节奏和近/中/远运镜短片；逐字字幕要看播放过程，不能只在单张截图上判断。短片通过后再开始完整导出。保持已通过的区域，问题在哪里就只修对应资产或图层。
```

## 完整导出指令

```text
使用当前工程tools/export-nancy.mjs导出，不能误用上游旧export脚本。输入同一已校准音轨与LRC。完整区间歌曲-5到211.96秒，1920×1080、60fps CFR，H.264高质量、AAC、BT.709 limited/yuv420p，faststart；目标13018帧、216.9667秒。导出成功后再将临时rendering文件原子改名。

优先使用可用的硬件编码与独立临时无头浏览器；GPU不兼容时使用软件回退。渲染逐帧取RGBA，不依赖浏览器实时播放速度，不漏帧、不按机器快慢改变动画。缓存可以优化性能，但不能改变renderFrame(t)的确定性。

现有指定MP3与参考分析音轨测得有1105/44100秒的前端裁切差，需补约25.0567ms。含5秒视觉片头的完整文件中，源MP3起点约为5.0250567秒。更换音源、采样率或裁切版本必须重新测量，不能盲套补偿值。音频先重采样，再按实际导出片段处理延迟或seek。

记录导出起止、帧数、尺寸、fps、音频补偿、编码、文件长度与哈希，便于校验和复现。
```

已有源码和依赖时，以下相对路径命令可用于当前实现；浏览器与 FFmpeg 的发现方式见项目 README。

```sh
npm install
node tools/nancy-server.mjs
node tools/render-nancy.mjs --out out/keyframes --gpu d3d11
node tools/render-nancy.mjs --times 19,59.9,90.5 --out out/revisions --gpu d3d11
node tools/export-nancy.mjs --start 82.04 --end 85.04 --out out/cat.mp4
node tools/export-nancy.mjs --start 148.04 --end 177.57 --out out/climax.mp4
node tools/export-nancy.mjs --start 92.3 --end 95.7 --out out/sun.mp4
node tools/export-nancy.mjs --start -5 --end 211.96 --width 1920 --height 1080 --fps 60 --cq 17 --out out/NancyLu_world_execute.mp4
node tools/verify-nancy.mjs out/NancyLu_world_execute.mp4
```

## 验证与交付

```text
对新导出的完整MP4执行严格全帧解码，检查13018帧、恒定60fps时间戳、H.264/AAC、BT.709、音画时长与快启布局。支持硬件解码的制作机可再做独立硬件解码交叉检查。抽取多个相距较远的音频窗口与源音轨做相关比对，报告实际测得的偏移，不只核对音频流时长。

黑帧检测要区分设计淡出与异常缺帧；画面检查至少覆盖关键帧、所有修改点、镜头首尾和短片。文字不能截断，猫爪不能缺拇指，无面段不能残留白五官，UI不能重复，太阳与年份不能脱轨。

重新渲染同一个t，并以不同跳转顺序重复，检查状态一致。允许硬件后期舍入的极小像素差时，说明比较方式与容差；跨设备不保证字节一致。不要把测试脚本“未发现错误”写成每帧美术绝对完美。

将实际通过的verify记录、关键帧总览、完整视频、短片、运行源码、真实留存提示词、重建模板、来源记录和资源说明整理成可交付目录。发布清单只列实际存在并核验的文件。检查压缩包完整性与链接后再交付，不将本机临时路径、缓存或私有配置加入源码。
```
